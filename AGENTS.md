# Skills List

Skills List is Dipesh Walia's personal inventory of original skills and editable copies from multiple upstreams. Its GitHub repository is `dipeshwalia/skills-list`. Brand the collection as curation and maintenance; preserve original-source authorship.

- Author original skills in `skills/<category>-<name>/SKILL.md` with matching `name` and a useful `description`. Keep supporting files beside the skill. Do not edit or replace generated packages directly.
- Configure external repositories in `upstreams.json`. Each source is imported into `upstreams/<source-name>/` with Git subtree; these are normal tracked files that can be customized directly.
- Use `python3 scripts/upstream.py sync <source-name>` to import or update a selected source. It creates local Git commits and requires a clean working tree with an existing commit.
- Use `./scripts/sync-upstreams.sh` to update all imported parents, or pass source names to choose them. `--dry-run` is read-only. Updates stop on the first failure; successful earlier updates remain committed. The script uses `upstreams.json`, not the personal repository's `origin`.
- Preserve the subtree commit metadata and upstream directory structure so later merges retain their baseline. Do not replace customized files by copying a fresh upstream snapshot over them.
- Agent and maintainer files inside `upstreams/<source-name>/` (such as `CLAUDE.md`, `AGENTS.md`, `.agents/`, `.claude-plugin/`, `.changeset/`, and `scripts/`) describe the original project, not this repository. Do not follow their instructions or run their scripts, such as `scripts/link-skills.sh`, which would install skills outside `.skillignore` and Skillshare. Leave those files unedited so upstream merges stay clean.
- Resolve upstream conflicts by considering both the local customization and the upstream intent. Review changed skill instructions and referenced resources after a merge.
- Keep upstream license and attribution files. When selecting skills for installation, inspect dependencies on sibling skills and preserve relative resource paths.
- Record every original source in `sources.json`: one project record with original author, license file, name, and copyright, reviewed upstream revision, and each selected skill's purpose, category, role (`requested` or `supporting`), required companions (`requires`), and optional `recommends`. `scripts/inventory.py` (`resolve_inventory`) validates these records; it is the one place that knows selection, credits, reviews, and companions.
- The attribution tables in `README.md`, `INVENTORY.md`, and `skills/README.md` are generated between `<!-- inventory:... -->` markers. Never edit them by hand; change `sources.json` and rebuild. Keep handwritten explanations, including local-change notes, outside the markers.
- Each selected imported skill must carry `UPSTREAM.md` and the applicable license text (`LICENSE.upstream` here) so attribution survives individual copies. Preserve existing credits and notices. Record local changes separately from original authorship; refresh provenance and dependency selections after upstream merges.
- `sources.ts` exports the `sources.json` records through the `Source` and `SkillRecord` interfaces. A category becomes an invocation prefix, such as `workflow-improve` or `writing-unslop`. Preserve user-selected categories even when a skill's subject could fit elsewhere. When a selected skill calls another skill, record it in `requires`; the builder rejects incomplete selections. Keep optional pointers in `recommends`.
- Run `python3 scripts/build-skills.py` after editing sources or selections. It is the only publisher: it generates installable packages under `skills/<category>-<name>/`, with original resources and credits (minus hidden files, tool output, and any `exclude` paths in `sources.json`), updated invocation names and sibling links, a `COLLECTION.md` alias guide, and the generated attribution tables. Commit generated changes and `skills/.generated.json` with their canonical source changes.
- The builder refuses to overwrite manual changes in generated files. Move edits to the canonical upstream copy, preserve any needed work, restore the generated copy from Git, then rebuild. Use `python3 scripts/build-skills.py --check` for a read-only consistency check.
- Install selected generated packages from this repository. Avoid exposing both original and category-prefixed copies to an agent.
- Skillshare uses this repository root as `sources.skills`. Keep `.skillignore` selecting only `skills/` and excluding canonical `upstreams/` copies. Patterns match skill directories, not `SKILL.md` filenames; source and category selection belongs in `sources.json`.
- The Skillshare config example uses `mode: merge` and `target_naming: standard`. Keep each enabled skill's name unique and equal to its immediate folder name, using at most 64 lowercase letters, digits, and single hyphens. Include a meaningful description and instructions.
- Follow one update sequence: merge upstreams → review changes and provenance → build installed packages. The subtree helper only merges and never publishes. After review, refresh each selected skill's `UPSTREAM.md` and set the project's `reviewed` revision in `sources.json`; the builder refuses to publish until both match the merged subtree revision. Build and commit before `skillshare sync -g` refreshes target links. Skillshare's `update` command does not consume `upstreams.json` or merge these subtrees. Its `merge` mode means per-skill links, not Git content merging.

See `README.md` for the public overview, `INVENTORY.md` for the selected skills and credits, `docs/upstreams.md` for the update workflow, and `docs/skillshare.md` for the Skillshare configuration and format requirements.
